## 2024-05-18 - [FirePillarDisplay loadedEntityList loop optimization]
**Learning:** Found an instance in `FirePillarDisplay.java` where `mc.theWorld.getLoadedEntityList()` was being iterated in `RenderLivingEvent.Pre<EntityLivingBase>`. Although it was gated by `mc.theWorld.getTotalWorldTime() % 5 == 0`, `RenderLivingEvent.Pre` is called for *every* living entity rendered per frame. This means on every 5th tick, the O(N) list scan was evaluated *M times* (M = number of rendered living entities), resulting in a severe O(M*N) lag spike every 5 ticks.
**Action:** Always decouple world state queries (like entity scanning/caching) from per-entity render events. Moved the logic to `TickEvent.ClientTickEvent` (checking `event.phase == TickEvent.Phase.START`) to ensure it only runs exactly once per tick.
